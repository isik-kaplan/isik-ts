# debug (`@isikk/core/debug`)

A developer console that stays quiet until someone asks for it. It provides namespaced loggers and
one switch that survives a reload. The console patch keeps every call flowing to whatever wraps
the console after it, such as Sentry's breadcrumbs, while deciding what reaches the screen. Nothing
happens on import: each piece is a function the app calls, in the order it needs.

## The switch

```typescript
import { debug } from '@isikk/core/debug'

debug(true) // every namespace
debug('app:*,-app:sql') // a pattern: `*` matches anything, and `-` leaves a namespace out
debug(false) // off
debug() // the pattern in force; '' is off
```

It's stored in `localStorage.debug`, the `debug` package's convention, so it survives a reload and
`localStorage.debug = 'app:*'` from devtools works too. It's off by default. Turning it on in
development, or for a user with a developer flag, is the app's call:
`debug(process.env.NODE_ENV === 'development' || user.isDeveloper)`.

While a namespace is off, its lines are held back in a ring buffer (the last 200 by default;
`configureDebug({ buffer })` changes that). Turning the namespace on prints them, in order. That
way, what happened before somebody opened the console isn't lost.

## Loggers

```typescript
import { createDebug } from '@isikk/core/debug'

const log = createDebug('app:tasks')
log.info('loaded', tasks.length)
await log.group('Save', async () => {
  // a click, the request it caused, and what changed nest under one group
  await api.tasks.update(id, body, { etag, idempotencyKey })
})
log.extend('sql') // app:tasks:sql
```

`log`, `info`, `warn`, `error` and `debug` print with the namespace first. `group(label, fn)` opens
a console group, runs `fn`, and closes the group when `fn` returns, throws or (for a promise)
settles. `enabled` says whether the namespace prints right now.

## The console patch

```typescript
// instrumentation-client.ts
import { quietConsole } from '@isikk/core/debug'

quietConsole() // first: Sentry adopts the patch as the console's own methods
Sentry.init({ ... })
```

After `quietConsole()`, a `console.*` call prints only while its namespace is on. A logger's call
is under the logger's namespace, and any other call (yours, a library's) is under `console`, or the
`namespace` you pass. Everything else is held for replay. Call it **before** `Sentry.init`. Sentry
wraps whatever the console holds at that moment, records a breadcrumb, then calls through, so it
still sees every call even when nothing reaches the screen. The browser's own lines (CSP, CORS,
failed loads) don't go through `console.*`, so no patch can hide them. It returns a function that
restores the console.

## Requests from a generated client

```typescript
import { createDebug, logRequests } from '@isikk/core/debug'

import { createClient } from './api/client'

const api = createClient({ baseUrl, fetch, onRequest: logRequests(createDebug('app:api')) })
// → PATCH /v0/tasks/t1/ { idempotencyKey, etag }
// ← 200 PATCH /v0/tasks/t1/ 42ms (req-7f3a)
```

A client generated by `isikk-gen-client` takes `onRequest`, which gets an event when each request
starts and when it ends. The events carry the method, path template, URL, idempotency key, etag,
status, time, and the response's `X-Request-Id`. A request with no answer gets an `error` event
instead and still throws. An observer that throws never changes the request. `logRequests` turns
the events into log lines, with error statuses as warnings and failures as errors.

Cross-origin (the app on `example.com`, the API on `api.example.com`), the browser hides
`X-Request-Id` from scripts until the API lists it in `Access-Control-Expose-Headers`. Before that,
`requestId` is always `null`. With django-cors-headers, that's
`CORS_EXPOSE_HEADERS = ["X-Request-ID"]`. A same-origin API needs nothing.
